# Index

Every doc and every directory of code, as a tree.
Add a line when you add a doc or a directory.
A source file has no line here: its header comment says what it is, and `tooling/index-coverage.ts` checks that it has one.

- [`README.md`](../README.md): what Jambot is and how to run it
- [`AGENTS.md`](../AGENTS.md): house rules and core structure (`CLAUDE.md` imports it)
- [`LICENSE`](../LICENSE): MIT
- `docs/`
  - [`MEMORY.md`](MEMORY.md): the cheatsheet and pointers to the topic files, the entry point
  - [`INDEX.md`](INDEX.md): this tree
  - [`ROADMAP.md`](ROADMAP.md): where the project is heading
  - [`architecture.md`](architecture.md): the workspace, the theory, layers (engine and its rates, transport, renderers, UI), delivery, languages, nodes (web clients, root node, rendering nodes), related projects, timing, and what has settled and what is open
  - [`development.md`](development.md): setup, toolchain and why it was chosen
  - [`prototype.md`](prototype.md): what the port keeps and changes, and how the port is checked
  - [`language.md`](language.md): the language design (#7) as a negative shape: the catalogue of constraints on Jambot's internal musical expression, each a claim with a witness, a counterexample and a test; tensions, candidates, experiments, and the names functional programming and category theory give its shapes
  - [`quinetic.md`](quinetic.md): #39's catalogue of quinetic properties (round trips, machine laws, convergence), each a claim with a test, or an alias of the `language.md` entry that already holds it
  - [`ratchet.md`](ratchet.md): how a working track and a negative track drive each other, with tests as the pawl (#37 and #7)
  - [`theory.md`](theory.md): the mathematics under `packages/theory` (circle, helix, generator, modes, composition, meter), each relation with the test that holds it
  - `docs/memory/`: facts that stay true, one file per topic, read on demand (they are not part of the boot set)
    - [`engine.md`](memory/engine.md): the levels, the band, the Muse, the style, swing and the clock
    - [`web-app.md`](memory/web-app.md): the screen, its components and what the end-to-end checks rely on
    - [`session.md`](memory/session.md): host and client mode, the fault kit, the timing panel
    - [`midi.md`](memory/midi.md): ports, panic and the drum note maps
    - [`theory.md`](memory/theory.md): reading names, the helix, Strudel, music21 and tonal
    - [`score-language.md`](memory/score-language.md): the score's layers, drums, meter and pitch syntax
    - [`analyzer.md`](memory/analyzer.md): the parser and its ladder
    - [`testing.md`](memory/testing.md): showing a gate fire, and the checks behind the house rules
    - [`ratchet.md`](memory/ratchet.md): the method's catalogues and pawl
    - [`prototype.md`](memory/prototype.md): running the prototype and what it does
    - [`repository-and-ci.md`](memory/repository-and-ci.md): CI, Pages, toolchain pins and the license
    - [`terms.md`](memory/terms.md): root node, rendering node, dough
    - [`hardware.md`](memory/hardware.md): the live setup
  - `docs/briefs/`: task briefs, kept verbatim
    - [`analyzer.md`](briefs/analyzer.md): the MIDI → score analyzer (#3)
    - [`host-mode.md`](briefs/host-mode.md): a plan sketch for host and client mode: the seams, the Muse on both sides, time, links
- `prototype/`: the baseline the port is oriented by
  - [`README.md`](../prototype/README.md): concept, spirit, prototype architecture, the score language, the plan for learned models, open threads
  - [`jambot-prototype.html`](../prototype/jambot-prototype.html): the playable single-file prototype
  - `prototype/experiments/`: measurements on the prototype for the language design (E1, E8)
- `packages/`
  - `packages/theory/src/`: music theory on one primitive, pure TypeScript (#28); its `index.ts` is the barrel
  - `packages/theory/experiments/`: measurements on the theory for the language design, outside the pure `src/` (E12)
  - `packages/engine/src/`: the musical engine, pure TypeScript: the machines of every level, the parts, the Muse, the style and the transport
  - `packages/engine/experiments/`: measurements on the port for the language design, outside the pure `src/` (E9 to E19)
  - `packages/score/src/`: the score, a bar as text and the text as a bar, pure TypeScript (#13, the seam of #63); the engine and `@strudel/mini` are dev dependencies, for its tests only (L4)
  - `packages/session/src/`: host and client mode, pure TypeScript ([brief](briefs/host-mode.md)): the lobby and session protocols, clocks, the fault kit and timing counters
  - `packages/analyzer/src/`: the parser, pure TypeScript (#141, the analyzer brief's steps 1–3, [brief](briefs/analyzer.md)): MIDI into tracks, tempo, swing, roles and the step grid
  - `packages/analyzer/experiments/`: the parser on real files, and its ladder (Q10)
- `apps/`
  - `apps/lobby/src/`: the lobby server, sessions found by name and relayed over WebSockets (`pnpm lobby`); `apps/lobby/` also holds `load.ts` (the load test), `Dockerfile` and `fly.toml` (hosting on Fly.io, `pnpm lobby:deploy`)
  - `apps/web/src/`: the browser app (Svelte 5, Vite, PWA): the page, the player, the screen's view model and the conductor; it serves the prototype at `/prototype.html`
  - `apps/web/src/components/`: the page's components, which take props and send intents
  - `apps/web/src/components/glyphs/`: the living pictures in the cards' summaries, drawn on `Glyph`'s frame
  - `apps/web/src/screens/`: the lobby at the door, the band behind it and the timing test the door leads to, presentational; the page (`App.svelte`) picks between them
  - `apps/web/src/timing-test/`: the timing test (#204, A7): its patterns, the matching of taps to hits, the run record and its download, the runs kept in the browser, and the container that plays it
  - `apps/web/src/session/`: host and client mode in the app ([brief](briefs/host-mode.md))
  - `apps/web/src/audio/`: the player's outputs: the built-in synth, MIDI out, the device's clock pairing
  - `apps/web/src/midi/`: Web MIDI in, the playing surfaces, routing and settings
  - `apps/web/e2e/`: the end-to-end checks, the built app in Chromium with its audio measured (`pnpm e2e`)
- `tooling/`: the repository's own gates and tools: `pnpm verify`, lint rules, hooks, the pawl, the license gate, the Pages deploy, screenshots
- `.github/`
  - `.github/workflows/ci.yml`: lint, format check, typecheck, tests, e2e, build; started by hand only
  - `.github/ISSUE_TEMPLATE/`: the epic, design, bug and infrastructure issue forms, one per label
  - [`.github/pull_request_template.md`](../.github/pull_request_template.md): the checklist every pull request fills in
- `.githooks/pre-push`: runs `pnpm verify` before a `git push` of a branch, and blocks the push if it fails; refuses a dirty tree, remembers a tree that passed, and runs the docs check alone for a markdown-only branch
- `.claude/`
  - `.claude/settings.json`: the session-start hook, the GitHub tools denied, and the checks agents may run without a prompt
  - `.claude/hooks/`: session start, resume and compaction, and the branch status line
  - `.claude/skills/`: project skills for agents
    - `.claude/skills/lobby-deploy/`: deploys the lobby to Fly.io from a session, and checks it answers
    - `.claude/skills/music-theory/`: checks theory claims against music21 and tonal
    - `.claude/skills/ratchet/`: claims in the Dialectica form and the moves both sides of a ratchet pair make (#41)
    - `.claude/skills/review-pr/`: reviews a pull request against the house rules, in its own worktree
    - `.claude/skills/land/`: merges a reviewed pull request, runs the deploy and checks the live site
    - `.claude/skills/screenshot/`: measured options shown side by side, as screenshots and as audio through the app's synth
